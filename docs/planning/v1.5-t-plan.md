# v1.5 T 阶段拆分计划

状态：**已完成。T1–T5 全部通过门禁；v1.5.0 已形成可审核发布候选。**

## 1. 执行规则

- 每个子阶段只有一个主要风险中心，后一阶段只能依赖已通过门禁的前一阶段。
- 每阶段建立 `docs/reports/stages/v1.5-tN-progress.md`，登记过程、故障注入、证据和限制。
- 每阶段单独 Git commit。T1–T4 完成不代表 v1.5 已发布。
- 不以文档勾选代替可运行证据，不以旧案例成功代替公共 SDK 验收。
- 大型实验可以复用已有冻结制品，但必须验证来源、哈希和协议，并至少运行一个通过公共 Job/Worker 的真实小任务。

## 2. T1：Research Project Bundle v2

### 目标

将范围阶段 Bundle v1 升级为能迁移完整 v1.5 Project 的 Bundle v2，消除 Plugin、Job、Conversation 和高级科研状态无法导出的缺口。

### 交付物

- Bundle v2 manifest、JSON Schema、哈希树、版本协商和 Bundle v1 兼容路径。
- 完整状态清单：Project/事件/投影，Conversation/候选/策略，问题/证据/假设/protocol/study/统计/评审/决策，Job/attempt/log/Artifact，Project/Workspace 插件锁、Scenario 依赖和项目记忆。
- Artifact 支持内嵌、内容地址、可验证缺失、因权限不可导出四种状态。
- 导入前 staging validation；验证期间不得修改目标实例。
- 导入兼容报告：`ready`、`degraded`、`blocked`，明确缺失插件、不兼容版本、外部 Artifact 和 core/schema 差异。

### 安全要求

- API key、Bearer token、confirmation token、secret provider 内容和敏感环境变量不得进入 Bundle 或哈希输入。
- 私有 Artifact 默认不内嵌。
- 未知对象、未知 schema、哈希不符和路径逃逸 fail closed。
- 导入不得静默安装插件、下载制品、扩大权限或执行代码。

### 门禁

1. 含 Conversation、Job、插件锁和高级 study 的 Project 可迁移到全新实例。
2. 导入后事件、投影、科研对象和非私有 Artifact 哈希一致。
3. 缺失或不兼容插件被明确报告；历史可读，执行状态降级或阻止。
4. manifest、事件、对象、Artifact 或插件锁任一篡改均被拒绝。
5. secret 扫描、迁移回滚、v1 upcast 和跨实例测试通过。

**停止点：** 完成 T1 报告、提交和推送后停止，不迁移真实案例。

## 3. T2a：多模态 MLLM Scenario 公共 SDK 迁移

### 目标

将已有 MLLM routing generalization 研究迁移为独立 Scenario，只通过 Core Service、公共 SDK 和 Job/Worker 读取冻结制品、执行评估、记录事件并生成 Bundle v2。

### 执行方式

- 复用 v1.4 已冻结的大型模型结果，核对原协议、commit、模型、数据和 Artifact 哈希。
- 至少运行一个真实、廉价的多模态数据检查或评估 Job，不能只重放 JSON。
- 明确保留 RIO 回答格式混杂和受限 transport 结论，不扩大科学主张。

### 门禁

1. Scenario 不引用内部 Store、Workflow、Domain 或 migration。
2. 所有新增状态只经客户端 SDK/Core Service。
3. 至少一个真实多模态小任务通过公共 Job/Worker 成功执行。
4. 复用制品的来源与哈希全部验证，不伪装成新模型运行。
5. 生成可跨实例导入的 Bundle v2，导入后依赖与 Artifact 状态明确。

**停止点：** 完成 `v1.5-t2a-progress.md`、提交和推送后停止，不开始 AG News。

## 4. T2b：fastText / AG News Scenario 公共 SDK 迁移

### 目标

迁移一个与多模态任务明显不同的文本分类 Scenario，验证公共核心不是围绕视觉任务特化。

### 执行方式

- 使用真实 AG News 数据和 fastText，执行可重复的 baseline/候选或等价有界实验，不能只重放历史 JSON。
- 数据、实验单位、Evaluator、Analyzer、失败语义和 Artifact 均通过 Scenario SDK 声明。
- 只通过 Core Service、Python/TypeScript 客户端 SDK 与 Job/Worker 驱动。

### 门禁

1. Scenario 不引用内部 Store、Workflow、Domain 或 migration。
2. 所有状态变化只经客户端 SDK/Core Service。
3. 真实文本分类实验成功，日志、资源和 Artifact 可审计。
4. baseline、实验单位、统计、FactLedger 和发布门禁不回退。
5. 与 T2a 形成跨类型比较，但不据此宣称广义跨学科泛化。
6. 生成并跨实例导入 Bundle v2。

**停止点：** 完成 `v1.5-t2b-progress.md`、T2 双案例汇总、提交和推送后停止，不开始能力评分。

## 5. T3：Research Capability Benchmark v1

### 目标维度

1. 问题与范围；2. 文献检索与全文证据；3. 创新性边界；4. 竞争假设；5. 实验设计与混杂；6. baseline 与执行；7. 序贯决策；8. 统计与实验单位；9. 失败诊断；10. 记忆提升；11. 科学写作；12. 复现与发布。

### 交付物

- 版本化 benchmark manifest、fixture、runner 和结果 schema。
- 每个维度至少一个成功用例和一个应拒绝或降级的对抗用例。
- 机器门禁、人工评价字段、输入/输出/Artifact 哈希与环境记录。
- 分维度基线报告；禁止只发布单一总分。T2 真实案例与合成 fixture 分开报告。

### 门禁

1. 相同 commit、fixture 和配置得到相同机器门禁结果。
2. 对抗用例不能因“流程完成”而通过。
3. 缺测显示 `not_evaluated`，不得当作零分或通过。
4. 结果可比较两个核心版本，并记录 schema、模型、成本和时间。
5. runner 只通过公共 SDK 使用核心。

**停止点：** 完成基线报告、提交和推送后停止，不修改发布元数据。

## 6. T4：开源发布工程

### 交付物

- Apache-2.0 `LICENSE`、必要 NOTICE 和第三方许可证说明。
- `CONTRIBUTING.md`、Code of Conduct、安全报告方式和支持边界。
- Scenario、Plugin、Worker、客户端 SDK 扩展教程，以及 Scenario/Plugin/RFC/ADR 模板。
- package 发布边界、`files`、exports、版本和安装 smoke test。
- 兼容承诺、弃用与迁移政策。

### 门禁

1. 打包产物不含数据库、secret、缓存、大模型、私有数据或无关制品。
2. 第三方 fixture 只依赖发布包即可实现 Scenario、Worker client 和插件 descriptor。
3. README 快速开始在干净临时目录可运行。
4. 文档链接、许可证归属、公共导出和生成文件一致。
5. 本阶段不创建远程 release 或 Git tag，只准备可审核 release candidate。

**停止点：** 完成 T4 报告、提交和推送后停止，等待 T5。

## 7. T5：v1.5 正式发布验收

### 验收矩阵

- 全量类型、单元、集成、契约、边界和文档测试。
- schema 3/10/11/12/13/14/15 到最终 schema 的迁移与故障回滚。
- Bundle v1/v2、跨实例、Artifact 和插件兼容故障注入。
- 服务认证、离线默认、SecretProvider、权限审计和 SSE。
- TypeScript/Python SDK、参考 CLI、T2a/T2b 两个真实 Scenario 和 T3 benchmark。
- fresh install、package contents、secret 和 license audit。

### 发布判定

- `pass`：全部强制门禁通过，可形成 v1.5 release candidate。
- `conditional`：只允许不影响科研正确性和安全边界的发布工程问题；缺失真实案例或 Bundle 完整性不能 conditional。
- `fail`：科研门禁、安全、迁移、公共兼容或真实案例任一失败。

### 交付物

- `docs/reports/releases/v1.5.0-report.md` 和机器可读 release audit。
- benchmark 索引、制品哈希、已知限制、升级步骤和回滚步骤。
- 可审核版本提交。Git tag、GitHub Release 或包发布需用户另行明确授权。

**最终门禁：** 只有 T1、T2a、T2b、T3、T4、T5 全部通过，v1.5 才能标记完成。
