# v1.3 规划：可靠性基础设施与真实研究联合迭代

## 目标

v1.3 分为 A、B、C 三条工作线。A 先完成并形成稳定底座；B 与 C 随后同步推进。

- **A：可靠性基础设施。** 修复真实多模态研究暴露出的数据模型、事实漂移、报告引用、数据替换和运行环境问题。
- **B：科研决策能力。** 强化竞争假设、判别实验、机制诊断和继续/停止判断。
- **C：第二项更真实的研究。** 使用自然场景文字、更大样本和更多模型持续检验 B，并把新瓶颈反馈到底座。

执行顺序为 `A → (B ↔ C)`。A 无需解决所有未来问题，但必须关闭已经观察到的严重可靠性缺口。

## A 阶段交付

### A1 通用实验单位

研究对象使用类型化 `ExperimentalUnit { id, kind, clusterId, attributes }`。Observation 使用 `unitId`，重复问题或条件继续使用 `group`。统计分析先在单位内聚合，再把单位作为独立样本。

旧 `seeds` 与旧 Observation 保留读取和分析兼容；迁移时生成 `seed:<value>` 单位。新研究不再需要把 image ID 塞进 seed 字段。

### A2 权威事实账本

确定性结果转换为带来源对象、JSON 路径和哈希的 `ResearchFact`。LLM 解释或评审必须返回事实断言；FactAudit 检查未知事实、数值不一致、重复断言和缺失必需事实。失败审计先入库，再阻止下游评审。

### A3 结构化声明与报告

关键数字使用 `{{fact.id}}` 引用。fact-bound 模板禁止自由数字；表格从账本解析值与来源。ClaimAssessment 可登记 `factLedgerId` 与 `claimFactIds`，最终报告生成结构化事实引用表。定性段落不得承载未绑定数值。

### A4 数据替换门

数据不可用不能直接触发静默替换。替换评估必须记录不可用证据，并比较实验单位、主要结果和目标构念。任一科学契约发生变化则拒绝；protocol 冻结后必须走 deviation、重新审批与冻结。

### A5 运行环境预检

Bubblewrap 在执行前检查 workspace、命令、挂载、prlimit、bubblewrap 和 GPU 设备节点。非零 GPU 的枚举桥显式列出连续设备前缀；缺失节点在模型加载前失败。预检结果可通过终端单独查看。

## 验收门

1. image/sample/run 等字符串单位完成配对聚类分析，未声明单位被拒绝。
2. v1.2 seed 数据迁移后保持可读、可分析；迁移失败完整回滚。
3. 注入错误效应值和缺失事实时，解释或评审在落入正式 Review 前失败。
4. 报告模板中的自由数字和未知 fact ID 被拒绝。
5. 替换数据改变实验单位、结果或构念时被拒绝；冻结 protocol 无 deviation 时被阻止。
6. 无效 workspace、命令、挂载或 GPU 节点在执行前被预检发现。
7. 全量 TypeScript 检查、测试和文档检查通过。

## B/C 启动条件

A 阶段验收完成后，B 与 C 可以并行启动。C 的所有核心结果必须使用通用单位和事实账本；每一轮研究暴露出的新错误应先形成失败测试，再修改 B 或基础设施。
