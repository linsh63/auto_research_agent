# v1.6 X 阶段：远程 workspace、Artifact 与 confirmation

状态：**实现与本地门禁完成；原生矩阵正在运行**

## 已完成实现

- 公共 `PortableWorkspaceSpec`：`cas_sync`、`remote_existing`、输入 manifest、远端 alias、输出声明和传输配额。
- 跨平台相对路径门禁，拒绝 traversal、盘符/UNC、控制字符、空路径段和大小写碰撞。
- SFTP `.partial` 上传/下载、hash negotiation、断点恢复、配额、远端校验和原子提交。
- 外部 `RemoteDataAliasRegistry`，限制在 `<remoteRoot>/data`，不进入 Bundle。
- Linux Worker 实际探测 Bubblewrap、Python、prlimit 和 GPU；Bubblewrap 离线执行并记录 stdout/stderr 和资源使用。
- `SshRemoteJobWorker` 只在客户端持有 Core 状态与 lease token，验证输出后写入本地 CAS。
- confirmation capability 转换为无本地 source 的 `remote_alias` 只读 mount，manifest 必须和 sealed data role 一致。
- `ResearchApplication.createSshWorker` 与 `./ssh` 公共入口，供 CLI、Web 和游戏客户端复用。

## 本地真实验证

当前 Linux 环境启动真实非特权 sshd，完成 trusted profile、SFTP Worker 安装、CAS 输入同步、Bubblewrap 离线执行、日志/资源审计、输出双端 SHA-256 校验和本地 CAS 原子落盘。`remote_existing` fixture 只在远端读取，sealed fixture hash 在执行前后均不存在于本地 CAS。

故障注入覆盖取消、wall timeout、掉线恢复、配额不足、hash 错误、路径逃逸、大小写碰撞和 stale/重复提交。confirmation 原有一次性 token 门禁继续通过，并新增 remote alias manifest 绑定；lease 不暴露 sealed 数据 source path。
