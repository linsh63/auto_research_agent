## 完成内容

- 发布 Python Scenario/Worker SDK，并从 9 份公共 Schema 生成带哈希的类型。
- 契约化 DataAdapter、ExperimentRunner、Evaluator、Analyzer、DomainCapability 和 ScenarioManifest。

- 新增 schema 14 插件来源、静态目录、安装锁、生命周期和 Project/Workspace scope。
- 实现 PiPluginBridge，映射 extensions、skills、prompts、themes，以及声明式 tools、apps、MCP 和 Scenario。

- 本地安装固定版本和内容 SHA-256；Git 来源通过无 checkout 的静态 mirror 读取。

## 安全与故障验收

- 含“导入即写文件”副作用的 extension 在 refresh、search、inspect 和 install 期间从未执行。
- Pi extension 强制显示 `host.full`，skill 强制显示 `model`，不能靠自报权限降权。
- 缺少精确权限批准时安装失败；Agent 不能改变插件生命周期。
- 更新新增 network 权限时，沿用旧批准会失败；批准新集合后返回明确 permission diff。
- core schema 不兼容插件在安装前被拒绝。
- 安装后来源内容漂移会进入 quarantined，不能重新启用。
- disabled、removed、quarantined 插件不会出现在 `plugin.runtime`。
- 来源不可用时 runtime selection 明确失败，历史 installation 不被删除。
- Project 是默认 scope；Workspace 插件可被其 Project 读取。
- Pi settings、本地目录和 Git URL 来源均通过静态测试。
- 两个示例 Scenario 只使用公共 SDK；Scenario boundary check 通过。
- schema 14 迁移执行备份；损坏 migration 完整回滚至 schema 13。
- 全量 66 项测试通过，N–Q 和既有科研门禁无回归。

## 已知限制

- 远程 npm registry 只支持预先 staging 的绝对路径，尚未实现安全 metadata 下载。
- Core 只返回 enabled runtime selection，不会擅自加载第三方代码；部署者的 Pi session factory 负责使用该 allowlist。
- 网络 Service、认证和参考 CLI 属于 S 阶段。
- 插件锁和 Scenario 依赖尚未写入 Project Bundle，属于 T 阶段迁移验收。
- 当前 Bundle v1 遇到有效插件锁会 fail closed，避免生成缺失依赖的伪完整存档。
