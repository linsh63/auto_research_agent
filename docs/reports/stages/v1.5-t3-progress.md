# v1.5 T3 阶段进度：Research Capability Benchmark v1

状态：**完成，T3 门禁通过；下一阶段为 T4**

## 完成内容

- 建立 `research-capability-v1@1.0.0` manifest、24 个 fixture 和版本化 JSON result schema。
- 十二个维度各有一个 success fixture 与一个 adversarial fixture。
- runner 只导入公开 Client、Contracts 和 Server 包路径，不访问 Store、Workflow、Domain、migration 或数据库驱动。
- runner 在全新 Core Service 实例上真实执行 scope、Bubblewrap Job、资源调度、人工门禁、失败分类和 Bundle 跨实例行为。
- 每个 case 记录 input/output/Artifact hash、公共操作、机器结果和人工 rubric；人工状态明确为 `pending`。
- T2a/T2b 真实案例作为独立证据附加，没有混入合成结果或生成单一总分。
- 支持加载上一份结果，按 implementation hash 和 case 结果比较两个核心构建。

## 实施过程与修正

1. 公共 API 审计确认只有 5 个维度能得到完整或部分公共验证；其余科研能力虽然存在内部实现和历史测试，但不能经上层 SDK 使用，因此标记 `not_evaluated`。
2. 初版确定性哈希包含 Bundle Artifact hash。由于 Project ID 和导出时间随机，相同语义结果被误报为变化。
3. 修正后仍逐次保留 input/output/Artifact hash，但确定性门禁只使用 fixture hash、预期行为、能力结果、拒绝原因和 gate result。
4. 连续两次全新实例运行得到相同门禁哈希，0 个变化 case。
5. “baseline 与执行”和“复现与发布”只覆盖其中一部分，最终标记为 `partial`，避免扩大结论。

## 基线结论

当前公共核心完整展示问题/范围、序贯人工门禁和失败分类；部分展示执行资源与 Bundle 复现。七个科研能力维度尚无公共 SDK 操作，因此核心虽然具备较多内部科研机制，还不能让独立客户端完成完整科研流程。这个缺口应成为 v1.5 后续兼容承诺和 v2 核心升级的明确输入。
