没有发布单一总分。结果是 **3 demonstrated、2 partial、7 not_evaluated、0 failed**。`not_evaluated` 既不计零分，也不计通过；它说明能力可能在内部实现或旧流程中存在，但公共 schema 1.0.0 无法由上层产品独立调用和验证。

## 成功与对抗结果

十二个维度各含一项 success fixture 和一项 adversarial fixture，共 24 项。可公开执行的对抗项分别验证：过早 scope 批准被拒绝、资源不足不发 Worker lease、agent 不能代替用户批准、未知 failure class 被契约拒绝、Bundle 篡改被拒绝。不可公开执行的十四项明确返回 `not_evaluated`，没有因 fixture 文件存在或流程完成而标记为通过。

## 确定性与版本比较

在相同实现、manifest 和 fixture 上连续运行两次，确定性门禁哈希均为 `d954346b42b4f391308a627fb57d19a26067db985951619f01698e85ef350d2d`，case-level 变化为 0。每次运行仍独立保留 input、output 和 Artifact hash；Bundle 因随机 Project ID 与时间不同而产生不同内容哈希，这些审计哈希不进入语义门禁哈希。

结果 schema 支持记录 baseline/candidate implementation hash、schema 兼容性和逐 case 变化，可比较两个核心构建。当前首个基线的 comparison 是同一实现重复运行检查，尚未声称跨版本能力提升。

## 真实案例隔离

T2a MLLM 与 T2b fastText 报告作为 `external_real_case` 单独附加并锁定输入与 Artifact hash，没有与合成 fixture 汇成总分。它们证明两个真实 Scenario 可走公共执行和 Bundle 路径，但不能填补七个公共科研能力入口的缺测。
