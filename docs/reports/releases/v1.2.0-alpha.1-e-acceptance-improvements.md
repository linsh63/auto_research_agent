# E 阶段独立验收与整改清单

日期：2026-09-20
结论：**不合格，E 阶段需重新打开；F 阶段暂不开始。**

现有 typecheck、build 和20项测试均通过，但测试没有覆盖若干规划硬约束。`v1.2.0-alpha.1` 保留为历史实现节点，不代表 E 已通过独立验收。

## P0：发布阻断项

1. **补齐认知对象。** 规划要求 `AssumptionRegister` 和 `HypothesisSet` 及版本关系；当前只有单条 `Assumption`，没有 HypothesisSet schema、表、Store API 或 JSON Schema。E 至少建立 versioned aggregate，竞争假设内容生成仍留给 F。
2. **关闭 confirmation 后的所有同 run 变更。** 动态复现显示 confirmation visibility 后仍可新增问题。对 `add/select question`、scope approval、protocol draft/approve/freeze、deviation 等写操作统一增加 program terminal guard，只允许 `derive`。
3. **修正 deviation 语义。** 当前 `approved=false` 仍会把 protocol 改为 `deviated`，且允许 confirmation。未批准 deviation 只能保存为 request；批准后必须创建新 protocol version并重新 approval/freeze，或明确保持原 frozen protocol不变。
4. **完成 migration 证据。** 使用 SQLite backup API，并生成 artifact manifest snapshot；增加空库、真实 v1.1 JSON（不含 `profile`）、schema 2副本、迁移中途失败和从 backup 恢复的自动测试。

## P1：一起收口

- JSON Schema 覆盖 Program、AssumptionRegister、HypothesisSet、Approval、Freeze、Deviation、Visibility 和 Derivation，不只覆盖 intent/question/protocol。
- CLI 增加端到端 contract test，验证错误退出码和机器可读输出。
- `maxDerivedRuns` 从配置进入确定性门禁。
- 修正文档中的测试与链接计数，并在 corrective report 中逐项引用测试证据。

## 重新验收条件

- 新增上述 P0 的回归测试，且能复现“修复前允许、修复后拒绝”。
- 规划7.1的12项任务和5项退出条件逐条建立代码/测试映射。
- 全量 typecheck、build、tests、docs、skill validation、依赖审计和secret扫描通过。
- 创建 corrective release commit；独立验收通过后再更新 E 状态并允许进入 F。
