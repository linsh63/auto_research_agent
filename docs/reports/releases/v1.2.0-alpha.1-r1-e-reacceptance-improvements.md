# E 阶段第二次验收整改清单

日期：2026-09-20
结论：**r1 首次复验不合格；整改已完成，最终复验见 `v1.2.0-alpha.1-r2`。**

22项测试、构建和文档检查均通过，但规划中的研究链和失败恢复仍未被确定性门禁覆盖。本清单记录的问题已在 r2 中处理。

## P0：发布阻断项

1. **强制认知链。** `addProtocol` 目前只检查 selected question 和 scope approval，没有要求该 question 存在有效 AssumptionRegister 与 HypothesisSet。必须强制 `Question → AssumptionRegister/HypothesisSet → Protocol`，并增加缺失对象时拒绝的测试。
2. **实现真正的版本关系。** AssumptionRegister/HypothesisSet 目前只有 `version` 和任意 `parentId`，没有同 question/program 校验、supersede、freeze 或旧版本状态转换。新增版本时必须验证父对象范围并原子 supersede；protocol 只能引用明确版本。
3. **重做 deviation approval。** `recordDeviation` 可直接接受调用方传入的 `approved=true`；生成的新 protocol 也没有应用实际 requested change，只把文字追加到 `allowedChanges`。应始终先记录 pending request，再由独立 `approve-deviation` 接收完整 revised protocol payload、审批者和对象 hash，随后重新 protocol approval/freeze。
4. **补迁移失败恢复。** 003/003b 没有显式事务、异常关闭/恢复路径、部分迁移故障注入和从 backup 恢复后的自动 readback。必须验证失败不会留下可启动的半迁移数据库。

## P1：同时补齐

- CLI contract 增加缺参、未知命令、非法状态的非零退出码和机器可读错误测试。
- artifact manifest 测试至少包含一个真实 artifact，并核对路径、大小与SHA-256。
- corrective report 为每项 E 任务和退出条件链接到具体测试，避免只报告总测试数。
