## 能力边界

T3 仍为 3 个 demonstrated、2 个 partial、7 个 `not_evaluated`。`not_evaluated` 不计通过或零分；它表示公共 schema 1.0.0 尚未向上层暴露文献证据、创新性、竞争假设、实验设计、统计、记忆和科学写作等完整操作。T3 人工评价字段仍为 pending，机器结果与人工结果保持分离。

本轮只在 Linux x64 验收。macOS 和 Windows 尚未验证，Bubblewrap confirmation 执行仍依赖 Linux。跨系统开发与 Worker capability 分层按用户决定留给下一个版本。

## 升级步骤

1. 停止旧 Core Service 和所有写入 Worker。
2. 备份 SQLite 数据库、Artifact CAS、插件缓存、配置和外部 secret provider 配置。
3. 保存当前 package/commit、数据库 schema 和 `project.bundle` 审计信息。
4. 安装固定的 `auto-research-agent@1.5.0` tarball；不要使用浮动版本。
5. 启动服务，让迁移在事务和预迁移备份保护下完成。
6. 检查 `/v1/capabilities`、服务审计、Project 状态和依赖报告。
7. 对关键 Project 导出 Bundle v2，并确认插件与 Artifact 状态。
8. 运行 README quickstart 和部署环境的 Worker smoke test，再恢复写入。

## 回滚步骤

1. 立即停止 v1.5 服务和 Worker，防止继续写入。
2. 保留失败数据库、日志和 artifact manifest 供诊断。
3. 恢复升级前数据库与对应 Artifact CAS 备份；不能用旧版本直接打开已写入 schema 16 的数据库。
4. 安装此前固定的 package/commit，恢复匹配的配置和插件锁。
5. 在隔离目录核对 Project/Bundle hash 后再恢复服务。

源实例在 Bundle 导入兼容报告和 Artifact 状态完成人工检查前不得删除。
