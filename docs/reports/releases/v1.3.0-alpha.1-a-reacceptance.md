# v1.3.0-alpha.1 A 阶段重新验收

日期：2026-09-28  
结论：**alpha.1 未通过；缺口已在 [v1.3.0-alpha.2](v1.3.0-alpha.2-report.md) 完成整改并重新验收。**

## 验收方法

本轮不只检查测试是否通过，还检查“调用者不主动使用新接口时，系统能否阻止旧错误”。复验包含：

- 对照 `docs/planning/v1.3-plan.md` 的 A1–A5 和七条验收门；
- 搜索所有解释、评审、ClaimAssessment、protocol 与 sandbox 主路径；
- 执行最小反例，尝试提交无 FactAssertion 的 Review 输出和包含自由数字、无 FactLedger 的 ClaimAssessment；
- 核对数据替换检查是否进入 WorkflowCoordinator/protocol 状态机；
- 复查迁移、通用单位、统计和 bubblewrap 预检测试。

## 逐项结论

| 项目 | 结论 | 证据 |
| --- | --- | --- |
| A1 通用实验单位 | 通过 | 新 UnitObservation、未声明单位拒绝、按 unit 聚类统计和 schema 7→8 真实数据库副本迁移均通过。 |
| A2 权威事实账本 | 未通过 | FactLedger 与 Review 审计组件有效，但 `factLedger` 是可选参数；现有结果解释脚本完全未接入 FactAudit。 |
| A3 结构化声明与报告 | 部分通过 | fact-bound 模板能拒绝自由数字；CLI 和 ReviewStore 仍接受没有 FactLedger 的自由文本 ClaimAssessment，最终报告仍可直接输出这些文本。 |
| A4 数据替换门 | 未通过 | `assessDatasetSubstitution` 的纯函数和 CLI 正确，但 WorkflowCoordinator、protocol draft/revision 和 deviation 流程没有强制调用它。调用者可直接跳过。 |
| A5 运行环境预检 | 通过 | `runBubblewrap` 强制静态 preflight；workspace、命令、挂载、系统工具和 GPU 节点均在执行前检查。 |

## 可执行绕过证据

当前 schema 接受以下两种输入：

```json
{
  "reviewAcceptedWithoutAssertions": true,
  "claimAcceptedWithoutLedger": true,
  "freeNumericClaim": "The effect was 0.05."
}
```

此外：

- `scripts/h_interpret_results.ts` 直接调用 `model.generate(..., InterpretationSchema, ...)`，没有 FactLedger 或 FactAudit。
- `scripts/h_run_reviews.ts` 创建 `ReviewWorkflow` 时没有 FactAuditStore，调用 review 时没有 FactLedger。
- `research claim-assessment` 直接调用 `ReviewStore.addClaimAssessment`。
- `assessDatasetSubstitution` 在产品代码中仅由 CLI 命令引用，没有进入 protocol 状态转换。

## 七条验收门

1. 通用字符串单位和聚类分析：**通过**。
2. v1.2 迁移与失败回滚：**通过**。
3. 错误事实在解释或评审进入正式对象前失败：**未通过**；只在调用者主动传入 ledger 时成立，解释路径未覆盖。
4. fact-bound 报告模板拒绝自由数字与未知 ID：**通过**；但默认 ClaimAssessment 可绕过。
5. 数据替换改变契约或冻结后无 deviation 时被工作流阻止：**未通过**；检查器未接入状态机。
6. 无效运行环境在执行前发现：**通过**。
7. 编译、测试和文档检查：**通过**。

严格计为 **5/7 门通过**，A 阶段整体不应标记完成。

## 必须整改的最小范围

1. 新增统一的 fact-audited model stage，解释与评审都必须通过；去掉正式确认流程中的可选 ledger。
2. schema 8 的新 ClaimAssessment 必须绑定 FactLedger；保留单独的 legacy import 路径读取 v1.2 对象。
3. 最终决策与报告拒绝无 fact-bound claim 的新研究。
4. 将 DatasetSubstitutionAssessment 接入 protocol create/revise/deviation，保存评估对象与哈希；不能只提供 CLI 检查器。
5. 更新 H 案例脚本和 CLI，使默认路径覆盖事实账本、审计、结构化声明和报告。
6. 增加“尝试绕过门禁必须失败”的端到端测试，再重新发布 alpha.2。
