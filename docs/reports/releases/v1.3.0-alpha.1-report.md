# v1.3.0-alpha.1 发布报告：A 可靠性基础设施

## 结论

A 阶段完成，版本发布为 `1.3.0-alpha.1`。该版本关闭了首项真实多模态研究暴露出的五类严重问题：seed 专用数据模型、LLM 事实漂移、报告自由数字、静默数据替换和运行时晚失败。

## 交付结果

| 能力 | 结果 |
| --- | --- |
| 通用实验单位 | `ExperimentalUnit`、`UnitObservation`、按单位聚类统计 |
| v1.2 兼容 | seeds 自动映射为 `seed:<value>`；旧 observation 继续分析 |
| 事实核验 | FactLedger、FactAssertion、FactAudit、失败审计入库 |
| 评审门 | 错误或缺失必需事实阻止 StructuredReview 生成 |
| 结构化报告 | fact-bound 模板、fact table、ClaimAssessment fact 引用 |
| 数据替换 | 科学契约比较；冻结后强制 deviation |
| 执行预检 | workspace、命令、挂载、系统工具和 GPU 节点预检 |
| 终端入口 | 六项新命令可直接使用上述能力 |

## 验收

- `npm run build`：通过。
- `npm run check`：通过。
- `npm run check:docs`：40 个 Markdown 文件、0 个坏链接。
- `npm test`：35/35 通过。
- 重点可靠性测试：6 项通过。
- schema 7 → 8 正常迁移：旧 seed 单位保留。
- 已关闭的真实多模态研究数据库副本升级至 schema 8 后保持 `closed`，60 个旧标识完整生成60个兼容单位。
- schema 8 故障注入：事务完整回滚至版本 7。
- Review 事实漂移注入：错误效应值被拒绝，失败 audit 被保存。

## 仍然保留的边界

- FactAudit 核对账本内事实，不能自动证明研究构念有效或因果解释正确。
- 旧 v1.2 ClaimAssessment 可继续没有 FactLedger；新研究应使用 fact-bound 接口。
- GPU 枚举桥仍会挂载目标卡之前的设备节点，兼容性提高但设备节点隔离较弱。
- B 的科学决策能力和 C 的自然场景多模态研究尚未开始。

## 下一步

按 [v1.3 规划](../../planning/v1.3-plan.md)同步推进 B 与 C：在更真实任务中形成竞争假设、判别实验与机制诊断，并要求所有核心结果经过本版本的事实账本和结构化报告路径。
