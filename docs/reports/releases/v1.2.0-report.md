## 科研验收摘要

真实案例使用固定 ResNet-18、seeds 11/23/47、12 epochs 和单 GPU。CandidateFreeze 前只暴露 brightness 与 defocus blur severity 3；之后一次性释放 clean test、Gaussian noise 与 contrast severity 3。

primary estimate 为 AugMix minus baseline 的 +0.14757，95% interval [+0.11128, +0.18386]。系统将 claim 等级限制为 suggestive，因为独立 seed 只有3颗，并且只有一个 architecture、两个 confirmation groups 和一个 severity。完整报告见 [CIFAR-10-C / AugMix案例](../../cases/cifar10c-augmix-h.md)。

## RC 后正式发布整改

正式审计发现 confirmation token 已消费，但 ResearchProgram 的 visibility event 由案例脚本单独负责，存在遗漏风险。正式版将 token 消费、visibility event 和 program `confirmation_observed` 状态合并到同一 SQLite transaction，并增加集成断言。

同一轮审计还发现终态 decision 写入后 program/study 未关闭。正式版把 terminal `ResearchDecision`、program `closed` 和 study `closed` 合并到同一事务，并为两个 aggregate 增加断言。当前真实案例已完成状态对账；科学对象与结果未修改。

另外新增正式统计门禁 fixture：

- missing observation 在 `missingPolicy=fail` 下拒绝分析；
- 20个相关 corruption groups 仍只形成3个独立 seed units；
- Holm family 保存20个 comparisons。

H 案例数据库已补记唯一 confirmation visibility event；此整改没有修改 protocol、checkpoint、confirmation observation、analysis 或 claim。

## 已知限制

- CIFAR claim 只适用于冻结的 bounded case，grade 为 suggestive；
- 当前主机 cuDNN 不可初始化，案例使用原生 CUDA convolution；
- 本地7B模型的结构化输出有6次失败，失败被预算和账本保留；
- Docker权限仍不可用，但不是v1.2执行前提；agent代码已用bubblewrap真实验收；
- active wall time 由模型、sandbox和工具调用的资源记录计算，不包含等待人工门的暂停时间；
- 跨项目记忆收益和更多研究场景继续作为后续版本工作。

## 回滚

各阶段 migration 前的 SQLite online backup 与 artifact manifest 位于对应数据目录的 `backups/`。程序回滚不删除 schema 7 对象；需要数据恢复时复制阶段前 backup 到新路径验证，禁止原地覆盖当前研究库。
