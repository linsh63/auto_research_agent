# v1.3.0-alpha.2 发布报告：A 阶段强制门禁整改

## 结论

A 阶段通过重新验收，七项门禁全部满足。alpha.1 的组件已接入默认主路径，新研究不能再绕过事实账本、结构化声明或数据替换门。

## 整改结果

| alpha.1 缺口 | alpha.2 处理 |
| --- | --- |
| FactLedger 是可选参数 | 新 study 默认 `fact_bound_v1`；ReviewWorkflow 无 ledger 立即拒绝 |
| 解释未进入事实审计 | 新增统一 `ReviewWorkflow.interpret`；必需事实全部断言并持久化审计 |
| 自由文本 ClaimAssessment 可绕过 | fact-bound study 在 ReviewStore 层强制 ledger、template、fact IDs 和精确渲染文本一致 |
| 最终决策可忽略审计 | decision 要求 interpretation 与四维 review 五个通过的 FactAudit |
| 最终报告可输出无绑定 claim | 新研究无法创建无绑定 assessment，报告生成结构化事实来源表 |
| 数据替换只存在独立检查器 | DatasetSubstitutionRecord 进入数据库；protocol dataRoles 变化必须引用 accepted record |
| 冻结后替换未绑定 deviation | 替换记录必须引用当前 deviation，approveDeviation 验证后才能生成新 draft |
| H 案例仍走旧路径 | 解释、claim 构建和四维 review 脚本全部改用同一 FactLedger |

## 兼容策略

- schema 9 新建的 study 默认 `fact_bound_v1`。
- schema 8 及更早的 study 缺少该字段时解析为 `legacy_v1_2`，可继续读取与复现，不会被伪装成已经通过新门禁。
- 真实多模态研究数据库副本从 schema 7 升至9后保持 `closed`、60个单位完整、策略明确为 `legacy_v1_2`。

## 不可绕过性测试

- 无 FactLedger 创建新 study 的 ClaimAssessment：拒绝。
- ClaimTemplate、claimFactIds 与渲染文本不一致：拒绝。
- 新 study 的 review 未传 ledger：拒绝。
- 错误或缺失必需事实：审计失败并入库，不创建正式 review。
- 缺少 interpretation audit：最终决策拒绝。
- 缺少任一四维 review audit：最终决策拒绝。
- protocol dataRoles 改变但无替换记录：拒绝。
- frozen protocol 替换未绑定当前 deviation：拒绝。
- 最终决策 rationale 含自由数字：拒绝。

## 验收

- `npm run check`：通过。
- `npm test`：35/35 通过。
- H 脚本独立严格 TypeScript 检查：通过。
- schema 8→9 正常迁移与失败回滚：通过。
- 真实已关闭研究数据库副本迁移：通过。

## 最终边界

事实账本保证报告忠于已登记结果，不证明研究设计本身正确。科学构念、竞争解释与研究价值继续由 B 阶段加强，并由 C 的真实任务检验。
