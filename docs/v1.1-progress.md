## A 阶段过程记录

### 已完成

- 读取并落实 v1.1 规划中的 SQLite schema、内容寻址存储、配置和 worker 边界。
- 将数据库 schema version 从 V1 的 1 迁移到 2；旧 run 保持可读。
- 添加 `SourceRecord`、`DocumentVersion`、`Passage`、`Claim` 和 `ClaimEvidence` domain schema。
- 添加 evidence 表、FTS5 passage 索引、Claim-Evidence 关系和检索事件表。
- 添加 SHA-256 content-addressed artifact store。
- 添加项目 YAML 默认配置和 Zod 校验。
- 添加 JSONL retrieval worker、handshake、deadline、cancel 和崩溃清理。
- 安装独立 PaperQA2 `2026.8.12` worker 环境，固定 `requirements.lock.txt`；worker capability 已报告 `paperqa`。
- 添加 V1 证据迁移脚本，将 fastText run 的 12 个来源、12 个 document version 和 9 个摘要 passage 写入新库。
- 现有搜索流程已默认尝试 retrieval worker；worker 不可用时保留 paper-search fallback。
- 添加 `evidence-status`、`evidence-search`、`retrieval-check` CLI。

### A 阶段环境限制（不阻止发布）

- GROBID 容器和 Docling standard PDF pipeline 需要 Docker/大型可选依赖；当前环境未提供，已使用 pdftotext fallback，并在 release report 中记录。
- LitQA2/LFRQA 和人工 citation support 标注集需要单独下载/授权；当前已完成40条项目fixture的keyword/PaperQA2对照、实际PDF ingestion和Claim gate测试，不能外推为PaperQA2论文benchmark结果。

### A 阶段最终登记

详见 [v1.0.1 release report](releases/v1.0.1-report.md)。控制平面、数据库、worker、PaperQA2 capability、迁移、降级路径和离线门禁已完成；GROBID 容器和 Docling 完整解析因当前运行环境不可用，按降级规则记录为环境限制。

重新验收后，PaperQA2已实际执行passage ingestion/retrieval，七个工具进入pi，Claim gate进入报告路径，并完成keyword/PaperQA2同集对照。最终结论见[A–C重新验收报告](releases/abc-revalidation-report.md)。

## 最终登记

A、B、C 的 release report、测试结果和迁移验证均已完成。D 阶段随后选择 Digits 图像分类，并在不修改核心 `src/` 的情况下完成第二场景闭环。D 的协议、逐划分结果、审查响应和限制见 [v1.1.0发布报告](releases/v1.1.0-report.md)。

2026-09-19重新验收发现初版tag只达到骨架级别，随后完成补强。原tag保留为历史节点；补强结果由当前release commit和[A–C重新验收报告](releases/abc-revalidation-report.md)登记。

## D 阶段过程与最终登记

- 先定义 CV 场景契约，再实现 `examples/sklearn-digits/` adapter 文件。
- 使用五个预声明 stratified holdout 比较固定 RBF SVC 的原始训练与一像素平移增强。
- 实跑结果为 0.992000 对 0.993333；三项提升、一项持平、一项下降，全部进入报告。
- pipeline 经过两个人工门、独立 `needs_work` 审查、结构化响应后到达 `done`。
- 自动测试从17项增至18项；新增测试同时检查真实 CV 执行和核心文件无领域耦合。
- Docker daemon 权限不足，D 只登记 local-process profile；该限制不被表述为已通过。
