# 交给 Mac Codex：v1.6 Z 跨机验收

本文件用于让运行在真实 Mac 上的 Codex 完成 Auto Research Agent v1.6 最后一项门禁。执行前，用户只需准备一个可通过 SSH key 登录的 Linux Host alias。

## 用户先做的准备

在 Mac 的 `~/.ssh/config` 中配置 Linux 服务器。示例：

```sshconfig
Host ara-z-linux
    HostName <LINUX服务器IP或域名>
    User <Linux用户名>
    IdentityFile ~/.ssh/<私钥文件>
    IdentitiesOnly yes
```

确认以下命令成功：

```bash
ssh ara-z-linux 'uname -s && uname -m && node --version && bwrap --version && prlimit --version | head -1'
```

Linux 输出必须显示 Linux、Node.js 22、Bubblewrap 和 prlimit。远端工作目录请选择该 SSH 用户可写、专用于验收的绝对路径，例如：

```text
/data0/linsihan/ara-z-worker
```

## 直接交给 Codex 的 Prompt

将本文件作为附件或上下文交给 Mac 上的 Codex，然后粘贴下面的内容。只需替换两个尖括号占位符。

```text
你现在要在这台真实 Mac 上完成 Auto Research Agent v1.6 Z 阶段的最终 Mac→Linux 跨机验收。

仓库地址：https://github.com/linsh63/research_explorer_core
本机仓库目录：如果当前目录已经是 research_explorer_core 就使用当前目录，否则放在 ~/research_explorer_core
SSH Host alias：<SSH_HOST_ALIAS>
Linux 远端工作目录：<REMOTE_ROOT>

请严格执行以下工作，不降低或跳过门禁：

1. 确认当前系统确实是 Darwin，并记录 arm64 或 x64；确认 Node.js >=22.19、npm、ssh、sftp、ssh-keygen 和 ssh-keyscan 可用。
2. 若仓库不存在则 clone；若已存在，检查工作树。只有工作树干净时执行 git pull --ff-only origin main。不要覆盖或删除用户的本地改动。
3. 阅读 README.md、docs/planning/v1.6-plan.md、docs/reports/stages/v1.6-z-progress.md、docs/guides/z-mac-linux-acceptance.md，以及 scripts/validate_z_mac_linux.ts。
4. 运行 npm ci 和 npm run check。不要安装或要求 Docker。
5. 运行 SSH 前置检查：
   ssh <SSH_HOST_ALIAS> 'uname -s && uname -m && node --version && bwrap --version && prlimit --version | head -1'
   如果首次出现 host fingerprint，向用户显示 fingerprint，让用户从可信渠道核对后输入 yes。不要使用 StrictHostKeyChecking=no。
6. 执行真实验收：
   npx tsx scripts/validate_z_mac_linux.ts \
     --host <SSH_HOST_ALIAS> \
     --remote-root <REMOTE_ROOT> \
     --output docs/reports/validation/v1.6-z-mac-linux.json
7. 该脚本必须真实完成：
   - Mac CAS 输入经 SSH/SFTP 交给 Linux；
   - Linux Bubblewrap 离线运行 exploration；
   - Artifact 经双端 SHA-256 验证后回到 Mac CAS；
   - 一次性 confirmation token 被消费；
   - sealed confirmation 只通过 remote alias 只读挂载；
   - sealed 数据不进入 Mac CAS、日志或 Project Bundle。
8. 验证生成的 JSON：status 必须是 pass；client.os 必须是 darwin；exploration.status 和 confirmation.status 必须都是 succeeded；两个 sealed-data 布尔断言必须符合禁止回传要求。
9. 运行 git diff --check，并对仓库执行 secret 扫描：
   rg -n --hidden --glob '!node_modules/**' --glob '!.git/**' 'sk-[A-Za-z0-9_-]{16,}' .
   扫描必须无命中。不要把 SSH 私钥、密码、token、known_hosts 或本地数据库加入仓库。
10. 只允许新增或更新 docs/reports/validation/v1.6-z-mac-linux.json。不要修改门禁代码来让验收通过；如果失败，诊断真实原因并修复实现或环境，然后重新完整运行。
11. 验收成功后执行：
    git add docs/reports/validation/v1.6-z-mac-linux.json
    git commit -m "Record v1.6 Z Mac Linux acceptance"
    不要 push，由用户自行检查后上传远程仓库。
12. 最后简要报告：Mac 架构、Linux 架构、exploration/confirmation 状态、两个 Artifact hash、sealed-data 隔离结果、commit hash，以及用户随后应执行的 git push origin main。

如果必要输入缺失，只问一个简短问题；否则持续执行到验收成功或遇到无法由本机解决的明确外部阻塞。
```

## 验收成功后的用户操作

先检查 Codex 的提交：

```bash
git show --stat --oneline HEAD
git show --format= -- docs/reports/validation/v1.6-z-mac-linux.json
```

确认 JSON 不含主机地址、用户名、远端绝对路径、token 或其他凭据后上传：

```bash
git push origin main
```

然后在 Linux 开发服务器同步并完成最终 audit：

```bash
cd /data0/linsihan/auto-research-agent
git pull --ff-only origin main
npm ci
npm run audit:v1.6
```

此时 `docs/reports/validation/v1.6-release-audit.json` 应变为 `pass / release_candidate_ready`。实际创建 tag、GitHub Release 或 npm publish 仍需另行授权。
