# 自动科研 Agent 总体规划（第一版）

更新：2026-09-17。本文记录已确认的核心决策与实施顺序；首个真实案例、具体资源配额和详细接口仍待实施前确定。

## 1. 目标与第一版边界

本项目首先服务个人 **AI 学术研究**。研究者给出任务、约束和资源后，agent 要在**可核查的文献证据和可重跑的实验结果**上，完成“定义问题 → 建立证据 → 提出可检验假设 → 设计验证 → 执行实验 → 审查结果 → 决定下一轮”的闭环。长期目标是让核心流程适用于不同研究场景；学科和起点论文由每次任务指定，不写死在核心流程中。事实、推断、假设和实验观察分别存储；失败与负结果也进入研究记录。

**第一版的首要目标是搭建可运行的 pipeline**，而非保证提出可发表的新方法。先用模拟适配器验证骨架，最终必须在一个小规模真实任务上跑完闭环：选择有公开代码和数据、指标明确的 AI 论文，复现基线并检验至少一个改进假设，生成研究账本、可复现实验包和有来源的报告。假设被否定也属于有效结果。具体案例稍后筛选并由研究者确认；案例只用于开发和验收，不成为固定入口。

首版采用单条研究主线，可比较少量候选方案；并行树搜索、论文初稿生成、远程算力、跨项目记忆和经验提炼留待后续迭代。核心数据模型保留外部实验登记接口，但首版只验收可脚本化的 AI 实验。第二个性质不同的场景用于后续检验模块通用性。

任务输入定义为 `ResearchBrief`：问题或方向、领域、已知论文或数据、允许的数据/工具、资源与费用上限、成功指标、禁止事项、需要人工确认的节点。首版只处理公开材料；若关键字段缺失，agent 标记并请求补全，不自行填入看似确定的条件。

## 2. 底座与总体结构

**采用 pi SDK 作为首选底座，加一层项目自有的科研编排。**pi 承担模型调用、工具执行、会话和事件流；本项目负责研究状态、阶段转换、证据与实验记录、预算和人工确认规则。先做短期技术探针；若关键能力无法满足需求，再审视底座选择。当前 [pi SDK 文档](https://pi.dev/docs/latest/sdk)展示 `createAgentSession`、自定义工具、资源加载器、会话和事件 API。其会话树保存交互过程，科研对象则独立持久化，不能仅依赖聊天记录或上下文压缩后的摘要。

编排层采用 **TypeScript/Node.js**，通过单独的 pi 适配层接入 SDK；实验脚本和部分已有 skill 可由隔离的 Python 进程运行。技术探针核验包名、版本、模型接入、工具注入、事件订阅、会话恢复与取消。当前官方示例使用 `@earendil-works/pi-coding-agent`；网上仍有 `@mariozechner/pi-coding-agent` / `badlogic/pi-mono` 的旧示例，实施时以所固定版本的官方文档和实际 API 为准。首版使用一个可配置的默认模型，记录模型版本、用量与费用，保留阶段级模型配置入口。

```text
CLI（任务创建、进度、审批、报告路径）
          │
任务入口与配置校验 ── 人工确认节点
          │
研究工作流编排器（阶段、转移、失败恢复、停止条件）
          ├── pi 适配器（会话、模型、工具、事件）
          ├── 能力适配器（检索、全文、skills、代码执行、统计）
          ├── 场景适配器（数据、协议、指标、实验运行方式）
          ├── 研究账本（来源、主张、假设、实验、结果、决策）
          └── 预算与权限策略、日志和评估
```

模块边界如下；具体接口在技术探针后确定：

| 模块 | 责任 | 首版实现方向 |
| --- | --- | --- |
| `core` | 任务、状态、阶段输入输出契约、决策与停止原因 | 与 pi 解耦的类型和状态机 |
| `runtime-pi` | pi SDK 封装、工具注册、事件映射、会话恢复 | 单一版本适配层；不向业务层泄漏 SDK 类型 |
| `evidence` | 检索记录、文献元数据、原文定位、主张与来源关联 | SQLite 元数据 + 本地文件；先支持摘要和合法可得全文 |
| `research` | 候选方向、假设、反例、实验方案、评审 | 结构化产物 + 明确校验条件 |
| `experiment` | 环境、任务、运行、产物、指标、失败记录 | 本机受控脚本执行器；保留外部实验登记接口 |
| `adapters` | 各研究场景及外部服务的接入 | 能力接口，按需启用，不让领域规则进入 `core` |
| `report` | 证据链、结果表、限制、下一步 | 从账本生成可审阅简报 |
| `policy` | 人工确认、工具权限、预算、超时、停止 | 配置化硬上限；计划外操作暂停确认 |

依赖方向保持为 `CLI → 工作流 → 核心契约`，pi、检索服务、脚本执行器和存储实现通过适配器接入；`core` 不导入任何外部 SDK。研究对象采用带版本的 schema，迁移和格式校验由存储层负责。运行产生的论文、日志与实验文件放在独立数据目录，并记录内容哈希。

本地 SQLite 保存研究对象和关系，文件目录保存文献、日志与实验产物，pi 会话保存交互过程。首版记忆以**持久化、可追溯和中断恢复**为准；向量记忆、跨项目检索与自动经验总结在真实运行记录积累后单独设计。

## 3. 研究状态与运行闭环

一个 `ResearchRun` 包含任务快照、阶段状态、预算余额、所用工具/模型版本和事件日志。主要对象：`Source`（URL/DOI、版本、访问时间、定位信息）、`Claim`（事实/推断/假设、支持与反证）、`Idea`、`Hypothesis`、`ExperimentPlan`、`ExperimentRun`、`Finding`、`Decision`、`Artifact`。对象之间保存 ID 关系，使报告中的关键结论能回到来源或实验。

每个阶段写入结构化产物并通过验证器后才转移。初始状态为 `draft → evidence_ready → proposal_ready → plan_approved → executed → analyzed → reviewed → continue/stop`；允许阶段失败、人工退回、补证据和重跑。审查后可选择修正假设、扩大证据、再实验或终止，并记录理由。

研究者确认研究问题、实验计划和最终结论。经批准的实验计划写明指标、可改动范围、最大尝试次数、时间和费用上限；agent 可在该范围内自主运行和迭代。增加预算、新增依赖、使用新外部数据源或变更计划范围时暂停确认。实验代码只在独立工作区修改；依赖与数据固定版本并缓存，实验环境默认不联网。自动迭代同时受尝试次数、时间、费用和连续无进展次数约束，任何一项触顶即停止并记录原因。具体额度随首个案例确定，不能默认为无限。

检索可通过外部服务处理公开查询；工具调用应记录外发服务及内容类型。首版不向远程模型或检索服务发送未发表想法、私有代码和私有数据。最终报告前自动检查引用定位、指标计算和复现信息，再由独立审查步骤指出反例与局限，研究者确认结论。

首版最小闭环的输出要求：

1. 检索范围、关键词、时间和实际命中的文献及可访问性记录。
2. 至少一个可证伪假设；明确对照、指标、失败判据与资源估算。
3. 基线和候选实验的配置、代码提交或内容哈希、数据版本、环境、随机种子、日志、指标与异常。
4. 结论逐条关联文献或实验；相冲突与缺失的证据显式列出；保留负结果。
5. 一份研究简报和机器可读账本，可中断后恢复，并解释为何进入下一轮或停止。

对无法自动执行的研究任务，同一流程可生成 `ExperimentPlan` 并停在 `awaiting_external_result`，由研究者导入实际结果再继续分析。这是接口目标，首版验收以脚本实验为主。

## 4. Skills 接入策略

[技能清单](../skills-inventory.md)中的能力均纳入 agent 的能力目录，在合适阶段按需调用；一次研究任务不要求使用全部 skill。已安装技能没有统一的可执行接口：`anysearch`、`paper-search` 等提供 CLI 或脚本，`grilling`、`research-ideation` 等主要提供方法流程，另有混合型技能。因此设置两类适配器：

1. **方法流程适配器**：读取指定版本的 skill 指令，提供阶段目标和结构化输入；要求输出符合对象 schema，由验证器检查必填字段与来源关系。
2. **受控脚本适配器**：以明确参数、工作目录、超时和资源限制运行脚本；捕获退出码、标准输出、错误与产物路径，转换为统一结果对象。

每项能力登记来源、版本或内容哈希、触发条件、依赖、外部服务、失败语义和可用性检查。先让论文检索、新颖性检查、实验设计和结果审查支撑真实闭环，再补齐清单内其他能力并逐项验证。遇到缺少脚本或外部账号的能力，可使用方法流程适配器或报告不可用，不伪装成已自动执行。pi 的 [skill 发现目录](https://pi.dev/docs/latest/sdk)与本机 `~/.codex/skills/` 不同，需要显式加载。

| Skill | 首版接入形式 | 主要作用 |
| --- | --- | --- |
| `anysearch` | 受控 CLI | 网络检索和页面提取 |
| `paper-search` | 受控 Python CLI | 论文检索、去重与排序 |
| `grill-me` / `grilling` | 方法流程 | 任务澄清与人工决策节点 |
| `scientific-brainstorming` | 方法流程，按需调用辅助脚本 | 候选方向与反例 |
| `research-ideation` | 方法流程 | 多轮选题比较 |
| `idea-spark` | 混合适配 | 单个可证伪提案 |
| `scoop-check` | 方法流程，按需调用检索/文档脚本 | 具体贡献的新颖性核查 |
| `hypothesis-generation` | 方法流程，按需调用校验脚本 | 假设与判别性预测 |
| `experimental-design` | 方法流程，按需调用设计脚本 | 对照、重复与偏差控制 |
| `statistical-analysis` | 方法流程，按需调用分析脚本 | 统计审查与效应量 |
| `scientific-critical-thinking` | 方法流程 | 证据强度与结论边界 |
| `scientific-writing` | 方法流程，按需调用审计脚本 | 研究报告生成与一致性审查 |
| `peer-review` | 方法流程，按需调用审计脚本 | 独立审查；遵守稿件授权条件 |

现有部分技能尚未固定上游版本，且本地目录不一定附带许可证文件。集成前核对上游授权和依赖，优先引用并固定外部技能，不直接复制未经核对的内容。论文 PDF、全文与派生材料只在取得相应权限后保存或分发。

| 候选 | 已有能力与可借鉴点 | 第一版判断 |
| --- | --- | --- |
| [pi SDK](https://pi.dev/docs/latest/sdk) | Agent 会话、工具、事件和资源加载；[扩展](https://pi.dev/docs/latest/extensions)可注册工具 | **作为运行底座候选**；先做版本和 API 探针 |
| [Feynman](https://github.com/advaitpaliwal/feynman) | 基于 pi 的科研工作流，覆盖文献、来源核验、复现与实验等 | **重点做源码对照**，优先借鉴接口和产物设计；评估模块复用与许可证后再决定是否引入 |
| [Agent Laboratory](https://github.com/SamuelSchmidgall/AgentLaboratory) | 文献、实验、写作的多阶段研究助手与检查点 | 借鉴阶段划分和人工协作位置；不整体移植 |
| [AI Scientist v2](https://github.com/SakanaAI/AI-Scientist-v2) | 假设、实验、分析、写作及树搜索 | 借鉴实验反馈与搜索策略；其默认环境偏向 ML/GPU，且许可证需单独核查 |
| [AIDE](https://github.com/WecoAI/aideml) | 围绕指标迭代生成、调试和评估代码，保留搜索树 | 后续作为脚本/ML 场景实验优化器候选，不放入通用核心 |
| [MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/) | 记录实验参数、指标、代码版本和产物 | 作为实验追踪后端候选；首版先定义兼容接口，避免过早引入服务依赖 |

这是一轮架构级调查，不代表上述项目已通过代码质量、许可证、安全和维护状态审计。优先复用成熟的检索、文献标识解析、实验追踪与沙箱能力；本项目的价值应集中在跨场景研究状态、证据链和受控迭代。

## 6. 实施顺序与验收

1. **技术探针**：固定 pi SDK 版本；跑通启动、结构化工具调用、事件记录、取消与恢复；盘点现有 skills 的调用方式、版本和授权。产物是最小示例、依赖锁文件与能力矩阵。
2. **核心骨架**：定义对象 schema、阶段契约、状态机、SQLite/文件持久化和 CLI；用模拟适配器跑通完整流程，包括审批、失败、停止和恢复。产物是可检查的账本和简报。
3. **能力接入**：建立两类 skill 适配器与可用性检查，让清单内适用能力进入目录；优先完成真实任务必需的检索、选题核查、实验设计和结果审查。记录外部服务、版本和调用证据。
4. **首个真实场景**：选定一个公开 AI 研究案例，接入受控实验执行；完成基线、候选、分析、独立审查与一轮决策。产物是可重跑记录，包含失败与负结果。
5. **可靠性与评估**：验证故障恢复、预算截断、引用核查、重复实验和人工审阅；记录研究者审阅时间与错误类型。pipeline 稳定后，再优化跨项目记忆、模型分配和探索策略，并接第二种场景检验核心接口。

首版验收以可检查事实为准：一个真实任务能从输入运行到有依据的继续或停止决策；每个重要主张能定位到来源或实验；基线与候选可用记录的配置重跑；费用和耗时不越界；中断后不丢失已完成阶段；未找到证据或实验失败时不会编造肯定结论。所有列入能力目录的 skill 都应有可用性状态、适配方式和至少一次针对其能力的验证记录。研究价值与新颖性另行评估，不把正结果或论文初稿数量当作 pipeline 成功的替代指标。

## 7. 暂缓的决策与后续顺序

- **首个真实案例**：暂缓选择。实施到真实场景前，筛选公开代码、数据、清晰指标和可控算力的候选，由研究者确认。
- **具体资源配额**：根据案例和本机资源确定每轮费用、时间、尝试次数和计算预算；框架先实现硬上限接口。
- **第二场景及高级记忆**：在首版真实闭环稳定后决定。对跨项目记忆先明确要解决的失败模式，再选择索引或总结机制。
- **详细接口与组件**：技术探针和模拟闭环后定稿；保持 `core` 与 pi、检索服务、实验追踪后端之间的边界。
